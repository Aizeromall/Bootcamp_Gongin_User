## 수정 필요 사항 — 이번에는 수정하지 않음

### 1. 중요: 구장대여 구분의 문자열/정수 혼용

실제 `reservation.reservation_category`는 `varchar(50)`입니다. PyMySQL이 반환하는 `'1'`, `'2'`를
일부 코드가 정수 상수 `1`, `2`와 직접 비교합니다. 기존 모의 테스트의 정수 자료만으로는 이 문제를 놓칩니다.

| 시나리오 | 기대 | 실제 mock 재현 |
| --- | --- | --- |
| 대여 결제, 구장 총액 10,000 / 정원 10 / category `'2'` | 총액 10,000 | 1인 금액 1,000 |
| 이미 개인 예약이 있는 슬롯, category `'1'` | 대여 차단 409 | 대여 성공 201 |
| 이미 대여된 슬롯, category `'2'` | 대여 차단 409 | 대여 성공 201 |
| 대여 취소, category `'2'` | 정상 취소 200 | 없는 대여 404 |
| 개인 예약 취소 API에 대여 `'2'` 전달 | 전용 취소 API 안내 409 | 개인 취소로 처리 200 |

확인 위치:

- `python/FastAPI/match/payment.py:109`
- `python/FastAPI/ground/ground_reservation.py:127`, `:220`, `:373`
- `python/FastAPI/cancel/customer_match_delete.py:66`

권장 수정: DB 구조를 임의 변경하기보다 공통 예약 구분 파싱/정규화로 모든 비교와 슬롯 표시를 통일합니다.
`''`, NULL, 유효하지 않은 값은 의미를 별도 결정해야 하며, 임의로 개인 예약으로 간주하지 않습니다.
PR #17의 대여 중복 차단·전체 금액·전용 취소 요구사항과 직접 관련됩니다.

### 2. 중요: 소셜 회원 PK 48자와 일부 API 45자 제한 충돌

후속 상태: 사용자 승인으로 아래 세 API의 회원 ID 제한을 50자로 수정했습니다. 아래 재현은 수정 전 기록입니다.

전체 SHA-256 기반 소셜 PK는 48자이며 customer/FK 컬럼은 50자입니다.
아래 세 API에 유효한 48자 PK를 보내면 DB 연결 전에 `body.c_id_seq` 422로 차단되는 것을 재현했습니다.

- `POST /match/reservation` — `reservation.py:88`
- `POST /match/payment` — `payment.py:54`
- `POST /ground/reservation` — `ground_reservation.py:185`

권장 수정: 이 세 요청의 회원 ID 길이만 실제 DB 기준 50자로 맞추고, 정상·경계·초과 길이 회귀 테스트를 추가합니다.
최초 검증에서는 미승인 변경이라 수정하지 않았고, 이후 승인된 범위로 입력 길이만 변경했습니다.

### 3. 신고 source router는 있으나 main에 미등록

후속 상태: 사용자 승인으로 main.py의 `/report` include_router를 추가했습니다. 아래 내용은 수정 전 발견 사항입니다.

[PR #15](https://github.com/Aizeromall/Bootcamp_Gongin_User/pull/15)에는 `/report` 등록이 기재돼 있지만,
현재 main은 `report_router`를 import만 하고 `app.include_router(report_router, prefix='/report')`가 없습니다.
OpenAPI에도 `/report/insert`, `/report/list`가 없습니다. 실제 서비스 경로로는 사용할 수 없습니다.

별도 mock 앱에 source router를 연결하면 정상 신고 201, 같은 경기 아님 400, 본인 신고 400, 잘못된 유형 422를 확인했습니다.
이 source 검증을 실제 main 서비스 정상 동작으로 보고하지 않습니다.

### 4. 일반 회원가입 입력 길이가 실제 DB보다 큼

후속 상태: 사용자 승인으로 전화번호 20자·성별 10자·팀명 50자로 수정하고 경계/초과 입력 검증을 추가했습니다.

| 필드 | 요청 허용 최대 | 실제 DB 최대 |
| --- | --- | --- |
| c_phone | 30 | 20 |
| c_gender | 20 | 10 |
| c_team | 100 | 50 |

현재 입력 검증을 통과해도 실제 저장 시 DB 오류/잘림 위험이 있습니다. 실제 INSERT 실패를 확인하기 위해 DB에 쓰지는 않았습니다.
권장 수정은 기존 DB 길이에 요청 검증을 맞추는 것입니다. 팀 값 입력 정책은 서버 고정 여부도 함께 확인해야 합니다.

### 5. 기존 예약 데이터 중 구분 빈 값

후속 상태: 사용자 지시에 따라 더미 데이터로 간주하고 건너뜁니다. 실제 값은 변경하지 않습니다.

읽기 전용 집계 시 `reservation_category=''` 7건, `'1'` 1건을 확인했습니다.
개인/대여를 구분할 수 없는 기존 행은 `reservation_category=1/2` 조건의 내역·정원·차단 계산에서 제외될 수 있습니다.
원래 용도를 확인하지 않고 7건을 일괄 UPDATE하거나 의미를 추측해 보정하지 않았습니다.
